1. Що таке адаптивна верстка?

Адаптивна верстка — це верстка, після якої сайт на різних моніторах відображається гарно, зручно для читання і не потребує масштабування, а також немає необхідності в горизонтальному скролінгу.

Адаптивна верстка і дизайн — це перелік технік і концепцій верстки, розробки та дизайну сайтів, що забезпечують відмінне відображення на різних пристроях.

💧 Аналогія: вода приймає форму склянки, чашки чи пляшки — вона не «ламається», а підлаштовується. Хороший сайт працює так само: той самий контент, але різна «форма» залежно від екрана.

✅ Хороший адаптив

Текст читається без збільшення пальцями, кнопки зручно натискати, нічого не «вилазить» за край екрана.

❌ Поганий адаптив

Треба зумити, щоб прочитати, або гортати сторінку вбік. Користувач просто закриє сайт.

Базове правило: у <head> завжди має бути <meta name="viewport" content="width=device-width, initial-scale=1">. Без нього телефон вдає, що екран великий, і зменшує сайт.

2. Viewport — область, яку бачить користувач

Адаптивна верстка працює з viewport (в’юпорт) — це область, яку бачить користувач на екрані, коли заходить на сторінку сайту з будь-якого пристрою. Це не весь екран телефона і не вся довжина сторінки, а «віконце», крізь яке ми дивимось на сайт.

📸 Аналогія: уяви величезний мурал на стіні й рамку фотоапарата. Мурал — це сторінка, а те, що влізло в кадр, — viewport. Повернув телефон або змінив розмір вікна — рамка змінилась, і вміст треба переставити під неї.
🔍 Твій viewport зараз: …

Потягни край вікна браузера або поверни телефон — число зміниться. Саме це число перевіряють медіа-запити min-width і max-width.

Що змінює розмір viewport

  • зміна розміру вікна браузера на комп’ютері;
  • поворот телефона (портрет ↔ ландшафт);
  • адресний рядок, що ховається під час гортання;
  • екранна клавіатура.

Метатег viewport

Мобільні браузери за замовчуванням вдають, що екран завширшки близько 980px, а потім зменшують сторінку, щоб вона влізла. Тому без спеціального тега текст крихітний, а медіа-запити для телефона не спрацьовують (браузер вважає, що екран широкий). Тег у <head> каже: «використовуй справжню ширину пристрою». 

<meta name="viewport" content="width=device-width, initial-scale=1">

Розбираємо атрибути

Атрибут Що означає
name="viewport" Це інструкція саме для налаштувань області перегляду.
width=device-width Ширина viewport дорівнює ширині екрана пристрою (у CSS-пікселях, а не фізичних).
initial-scale=1 Початковий масштаб 100%: сторінка не збільшена й не зменшена.
minimum-scale, maximum-scale Межі масштабування пальцями. Краще не обмежувати.
user-scalable=no Забороняє зум. Не використовуй: людям зі слабким зором потрібне збільшення (вимоги доступності WCAG).
viewport-fit=cover Сторінка займає весь екран телефона, навіть під вирізом. Разом із env(safe-area-inset-top) тримаємо вміст у безпечній зоні.
📏 Аналогія: CSS-піксель — як «сантиметр на лінійці браузера». Екран iPhone має понад 1000 фізичних точок завширшки, але для верстки це приблизно 390 CSS-пікселів. Саме їх показує device-width, тому на різних телефонах верстка поводиться схоже.

Одиниці, що залежать від viewport

Одиниця Значення
vw / vh 1% ширини / висоти viewport
dvh динамічна висота: враховує адресний рядок, що ховається (найкраще для «на весь екран» на телефоні)
svh / lvh найменша / найбільша висота viewport

⚠️ Типова помилка: width: 100vw враховує смугу прокручування, і на комп’ютері з’являється горизонтальний скрол. Надійніше писати width: 100%.

Контрольний список

  • метатег viewport є в кожній HTML-сторінці;
  • не забороняємо зум;
  • не задаємо блокам фіксовану ширину в px більшу за екран телефона;
  • перевіряємо сайт у режимі пристроїв у DevTools (F12 → іконка телефона).

3. Два головні принципи

Mobile First — спочатку продумується, малюється і верстається мобільна версія сайту, а потім нарощується функціонал для більших екранів.

🎒 Аналогія: ти пакуєш рюкзак на день: спершу найнеобхідніше, а для довгої подорожі докладаєш речі. 
/* базові стилі = для телефона */
.cards { display: flex; flex-direction: column; gap: 1rem; }

/* від 768px картки стають в один ряд */
@media (min-width: 768px) {
  .cards { flex-direction: row; }
}

Використовуємо min-width. Це стандарт індустрії: більшість відвідувачів зараз із телефонів.

Desktop First — спочатку верстається десктопна версія, а потім прибирається все зайве, залишається мобільна версія.

🧳 Аналогія: ти зібрав велику валізу, а потім із неї вибираєш лише те, що влізе в рюкзак. 
/* базові стилі = для компʼютера */
.cards { display: flex; flex-direction: row; gap: 1rem; }

/* до 768px картки стають в один стовпчик */
@media (max-width: 768px) {
  .cards { flex-direction: column; }
}

Використовуємо max-width. Працює, але на слабких телефонах завантажується зайве, тому сьогодні частіше обирають Mobile First.

📌 Запам’ятай

У Mobile First базові стилі, написані без медіа-запитів, — це стилі для мобільного. Окремий @media для телефона писати не треба. Медіа-запити пишемо для більших екранів: планшета та комп’ютера, за допомогою min-width. 

/* телефон: без медіа-запиту */
.menu { display: flex; flex-direction: column; }

/* планшет */
@media (min-width: 768px) {
  .menu { flex-direction: row; }
}

/* комп'ютер */
@media (min-width: 1024px) {
  .menu { justify-content: space-between; }
}
  • Точніше казати не «для планшета», а «для екранів від такої-то ширини»: ми пишемо під брейкпойнти, а не під моделі пристроїв.
  • Медіа-запити потрібні не лише для розміру екрана: prefers-color-scheme (темна тема), prefers-reduced-motion (менше анімацій), print (друк), hover (чи є миша).
  • Щоб базові стилі справді працювали як мобільні, у <head> має бути метатег viewport.
  • Базові стилі мають бути гнучкими: %, rem, flex, max-width: 100%. Фіксована ширина в px на телефоні дасть горизонтальний скрол.

Коротко: Mobile First = базові стилі для телефона + @media (min-width: …) для великих екранів. Desktop First навпаки: базові стилі для комп’ютера + @media (max-width: …), щоб прибрати зайве на телефоні.

4. Коротка історія медіа-запитів

  • 1994 — Хокон Віум Лі (Håkon Wium Lie) у первісній пропозиції CSS згадує ідею медіа-запитів, але до CSS1 вона не потрапила.
  • 1997 — рекомендація HTML4 показує приклад того, як ці можливості можуть з’явитися в майбутньому.
  • 2000 — W3C починає роботу над Media Queries.
  • 2001 — перший публічний робочий проєкт медіа-запитів.
  • 2012 — специфікація стає рекомендацією W3C після того, як браузери додали підтримку.

5. Медіа-запити: з чого вони складаються

Медіа-запити роблять можливими сучасні адаптивні сторінки, які однаково добре виглядають і на десктопі, і на смартфоні. Все зводиться до застосування того чи іншого CSS-правила залежно від розміру вікна браузера (в’юпорту), налаштувань браузера або можливостей пристрою.

🚦 Аналогія: медіа-запит — це «якщо… то…». Якщо екран ширший за 900px — зроби фон зеленим, інакше — залишай як є. Як світлофор: умова виконалась і правило спрацювало.

Алгоритм роботи

1. Розробник описує медіа-запити та CSS-правила всередині них.
2. Браузер стежить за зміною розміру в’юпорту.
3. Браузер застосовує правила тих запитів, які відповідають поточному розміру.

Простими словами: «коли сторінку відкрили на десктопі — колір тексту червоний, а на телефоні — зелений».

Що таке директива?

Директива (в CSS її ще називають @-правилом, англійською at-rule) — це спеціальна інструкція для браузера. Вона завжди починається із символу @ і пояснює, як обробити блок коду, що йде після неї. Звичайні CSS-правила кажуть «зроби цей елемент червоним», а директива — «ось особливі умови або налаштування для цього блоку».

Директива Для чого
@media застосувати стилі лише за певних умов (розмір екрана, друк…)
@import підключити інший файл стилів
@font-face підключити власний шрифт
@keyframes описати кроки анімації
📣 Аналогія: уяви шкільне оголошення. Звичайне правило — «Усі сидять тихо». Директива — це заголовок «УВАГА! Під час контрольної:», після якого йдуть правила, які діють тільки тоді. @media теж каже: «Увага! Лише коли екран такий-то:» — і далі в фігурних дужках йдуть стилі.

Будова медіа-запиту

@media media-type operator (media-feature) {
  /* CSS-правила, які застосуються, якщо
     тип пристрою і умова виконуються */
}

operator — логічний оператор (and, not, only), який поєднує медіа-тип і медіа-функцію. Детально розберемо його в розділі 8.

Медіа-запит оголошується директивою @media, за якою може йти тип пристрою (media-type) і медіа-функції (media-feature) — вирази, що перевіряють характеристики пристрою, наприклад ширину в’юпорту. Медіа-функція — це логічний вираз, який повертає істину або хибність.

🖨️ media-type
НА ЯКОМУ пристрої? (екран, принтер…)
📏 media-feature
З ЯКИМИ характеристиками? (ширина, орієнтація…)
🔗 Оператори
Як ПОЄДНАТИ умови? (and, not, only, кома)

Розбираємо по черзі: спочатку типи, потім функції, і наприкінці оператори, які поєднують усе разом.

6. Медіа-типи (media-type)

Медіа-тип відповідає на питання «на якому пристрої показують сторінку?». Він пишеться одразу після @media.

Тип Опис
all Усі типи. Це значення використовується за замовчуванням.
print Друкуючі пристрої на кшталт принтера.
screen Екран пристрою.
speech Мовні синтезатори, а також програми для відтворення тексту вголос. Сюди, наприклад, можна віднести мовні браузери.
🎭 Аналогія: один і той самий сценарій можна показати в кінотеатрі (screen), роздрукувати на папері (print) або озвучити як аудіокнигу (speech). Зміст той самий, а «подача» різна.

Приклад: сторінка для друку

/* на екрані: меню і реклама видно */
nav, .ads { display: block; }

/* при друку: прибираємо зайве, економимо чорнило */
@media print {
  nav, .ads { display: none; }
  body { background: white; color: black; }
}

/* для програм озвучення (демонстраційний приклад, підтримка обмежена) */
@media speech {
  .decor { speak: never; }
}

Спробуй: натисни Ctrl+P на цій сторінці — у попередньому перегляді буде видно лише шпаргалку з розділу 14, а решту сторінки сховано директивою @media print. Це і є стилі для print у дії. Якщо тип не вказати, діє all. Тому @media (min-width: 900px) — це те саме, що @media all and (min-width: 900px). А от print корисний для чеків, квитків і конспектів.

7. Медіа-функції (media-feature)

Тип каже, де показують сторінку. Медіа-функція перевіряє, який саме цей пристрій. Їх велика кількість, повний список є на MDN. Основні функції, що найчастіше використовуються і дозволяють визначати ширину в’юпорту браузера, — min-width і max-width. Вказується мінімальна (min-width) або максимальна (max-width) допустима ширина в’юпорту, за якої застосовуються правила з медіа-запитів. 

/* Застосується, коли ширина в'юпорту 600px і менша */
@media (max-width: 600px) {
  body { background-color: yellow; }
}

/* Застосується, коли ширина в'юпорту 900px і ширша */
@media (min-width: 900px) {
  body { background-color: green; }
}
🎢 Аналогія: min-width — «мінімальний зріст для атракціону» (від цієї межі й вище), max-width — «до цієї межі включно».
Функція Перевіряє Приклад
min-width, max-width ширину в’юпорту (min-width: 768px)
orientation орієнтацію: portrait (вертикально) чи landscape (горизонтально) (orientation: landscape)
prefers-color-scheme темну чи світлу тему користувача (prefers-color-scheme: dark)
prefers-reduced-motion чи просить користувач менше анімацій (prefers-reduced-motion: reduce)
hover чи вміє пристрій наводити курсор (миша є, палець ні) (hover: hover)

8. Логічні оператори

Тепер, коли ми знаємо типи та функції, їх можна поєднувати. Медіа-тип і медіа-функції можуть бути розділені необов’язковими логічними операторами not, and і only. Повний синтаксис: 

@media only|not media-type and (media-feature) {
  /* CSS-правила */
}

Вертикальна риска | у записі означає «або»: можна написати only або not, а можна не писати жодного з них. Усе, що в дужках чи без них, — це частини одного запиту.

Оператор Що робить Приклад
and «І»: усі умови одночасно screen and (min-width: 600px)
not Заперечення всього запиту not print
only Приховує запит від дуже старих браузерів. Сучасні браузери працюють так само і без нього only screen and (min-width: 600px)
кома , «Або»: спрацює будь-яка умова (max-width: 500px), (orientation: portrait)
🎟️ Аналогія: вхід на концерт. and — «потрібен квиток І паспорт». Кома — «потрібен квиток АБО запрошення». not — «усім, крім учасників». 
/* екран І ширина від 600 до 900px */
@media screen and (min-width: 600px) and (max-width: 900px) {
  .menu { flex-direction: row; }
}

/* вузький екран АБО вертикальна орієнтація */
@media (max-width: 500px), (orientation: portrait) {
  .sidebar { display: none; }
}

/* усе, крім друку */
@media not print {
  body { background: #f6f7fb; }
}

У сучасних браузерах діапазон можна записати коротше: @media (600px <= width <= 900px), про це ще буде в розділі «Як це роблять у 2026 році».

9. Брейкпойнт (breakpoint)

Брейкпойнт (англ. breakpoint, «контрольна точка», «точка зламу») — це конкретне значення розміру в’юпорту (найчастіше його ширини), за якого в CSS спрацьовує медіа-запит і до сторінки застосовуються інші стилі, тобто змінюється макет.

  • Брейкпойнт — це число в умові медіа-запиту: у @media (min-width: 768px) брейкпойнтом є 768px.
  • Це не окрема CSS-властивість і не директива, а термін, яким розробники називають таку межу.
  • Брейкпойнт ділить ширину екрана на дві зони: «до» і «від» цього значення. Кілька брейкпойнтів утворюють діапазони: телефон, планшет, комп’ютер.
🌡️ Аналогія: вода при 99°C ще рідина, а при 100°C вже закипає. Число 100 — це «точка зламу», де змінюється стан. Так само сайт на 599px ще «мобільний», а на 600px уже перебудовується. 
.menu { display: flex; flex-direction: column; }   /* до 768px: стовпчик */

/* 768px — це брейкпойнт */
@media (min-width: 768px) {
  .menu { flex-direction: row; }                    /* від 768px: у рядок */
}

Типові брейкпойнти

Ширина Пристрій (орієнтир)
до ~600px 📱 телефон
від ~600px 📱 великий телефон, телефон горизонтально
від ~768px 📋 планшет
від ~1024px 💻 ноутбук
від ~1440px 🖥️ великий монітор

Як вибрати брейкпойнт

❌ Не так
«Зроблю під конкретний телефон». Моделей тисячі, і щороку з’являються нові.
✅ Так
Повільно розтягуй вікно браузера. Щойно макет став некрасивим (текст розтягнувся, блоки далеко), саме тут і ставимо брейкпойнт.
👕 Порада: не вигадуй багато брейкпойнтів. Для простого сайту зазвичай вистачає двох-трьох. Для Mobile First пиши тільки min-width, щоб діапазони не перекривалися. Спробуй у лабораторії нижче: там брейкпойнти 600px і 900px.

10. 🧪 Лабораторія: повзунок ширини екрана

Це справжня сторінка з медіа-запитами в рамці. Рухай повзунок і дивись, як вона перебудовується. Або тисни кнопку пристрою.

360px 

.row  { display: flex; flex-wrap: wrap; gap: 8px; }
.item { flex: 1 1 100%; }                                   /* 1 колонка */
@media (min-width: 600px) { .item { flex-basis: calc(50% - 8px); } }      /* 2 колонки */
@media (min-width: 900px) { .item { flex-basis: calc(33.333% - 8px); } } /* 3 колонки */

11. 🧩 Flexbox + адаптив

Flexbox розкладає блоки в рядок або стовпчик. Разом із медіа-запитами це найпростіший спосіб зробити меню й картки адаптивними.

🚌 Аналогія: flex-контейнер — це автобус, а блоки — пасажири. На вузькій вулиці (телефон) усі стоять в один ряд по вертикалі, а на широкій дорозі (десктоп) сідають поруч.

Приклад 1: меню змінює напрямок

.menu { display: flex; flex-direction: column; gap: 8px; }  /* телефон */

@media (min-width: 600px) {
  .menu { flex-direction: row; justify-content: space-between; }
}

Приклад 2: картки самі переносяться

.cards { display: flex; flex-wrap: wrap; gap: 12px; }
.card  { flex: 1 1 200px; }  /* росте, стискається, мінімум ~200px */

flex: 1 1 200px означає: «зайняти вільне місце, за потреби стиснутись, але бажано не менше 200px». Коли місця мало — картка переходить на новий рядок.

Приклад 3: сторінка з бічною панеллю

.layout { display: flex; flex-direction: column; }      /* телефон: все в стовпчик */
.side { flex: 0 0 200px; }
.main { flex: 1; }

@media (min-width: 900px) {
  .layout { flex-direction: row; }                      /* десктоп: панель збоку */
}
360px

Дивись: меню міняє напрямок на 600px, бічна панель стає збоку на 900px, а картки переносяться самі.

12. Як це роблять у 2026 році

Медіа-запити — основа, але сучасна верстка поєднує кілька інструментів. Менше «жорстких» брейкпойнтів, більше гнучкості.

📏 Відносні одиниці

Використовуй rem, %, vw, а не лише px. Для висоти екрана на телефонах — dvh, бо вона враховує рядок адреси браузера.

🪄 clamp()

Розмір, що плавно росте між мінімумом і максимумом без жодного медіа-запиту:
font-size: clamp(1rem, 2.5vw, 2rem)

🧱 Flexbox

Блоки самі переносяться: flex-wrap: wrap і flex: 1 1 15rem — і колонки підлаштуються самі, без жодного медіа-запиту. (CSS Grid ви вивчите пізніше, він для складніших макетів.)

📦 Container Queries

Компонент реагує на розмір свого контейнера, а не всього екрана: @container (min-width: 400px). Підтримується всіма сучасними браузерами.

🖼️ Адаптивні картинки

max-width: 100%, а також srcset і <picture>: телефон не мусить качати величезне фото.

🌗 Налаштування користувача

prefers-color-scheme: dark (темна тема) і prefers-reduced-motion (менше анімацій) — теж медіа-запити. Спробуй кнопку «Тема» вгорі!

Сучасний синтаксис діапазонів

/* замість (min-width: 600px) and (max-width: 900px) */
@media (600px <= width <= 900px) { ... }
👕 Аналогія: одяг бувають S, M, L (брейкпойнти), а гумка в поясі (clamp, %) підлаштовується плавно. Найкраще працюють обидва варіанти разом.

13. ✅ Перевір себе

14. 📄 Шпаргалка

Основні терміни та синтаксис на одній сторінці. Натисніть кнопку або Ctrl+P: надрукується лише ця шпаргалка.

📚 Основні терміни

  • Адаптивна верстка — верстка, за якої сайт на різних моніторах відображається коректно та зручно для читання, не потребує масштабування і горизонтального прокручування.
  • Адаптивний дизайн — сукупність технік і концепцій верстки, розробки та дизайну сайтів, що забезпечують коректне відображення на різних пристроях.
  • Viewport (в’юпорт) — область вікна браузера, яку бачить користувач на екрані будь-якого пристрою.
  • Директива (@-правило) — інструкція в CSS, що починається із символу @ і визначає, як браузер має обробити наступний за нею блок.
  • Медіа-запит — конструкція, яка оголошується директивою @media і застосовує вкладені CSS-правила лише тоді, коли виконується задана умова.
  • Медіа-тип — тип пристрою виведення: all, screen, print, speech.
  • Медіа-функція — логічний вираз, що перевіряє характеристику пристрою (наприклад, ширину в’юпорту) і повертає істину або хибність.
  • Логічні оператори — and, not, only і кома; поєднують умови в одному запиті.
  • Брейкпойнт (breakpoint) — конкретне значення розміру в’юпорту (найчастіше ширини), за якого спрацьовує медіа-запит і змінюється макет. Це число в умові, наприклад 768px у (min-width: 768px).
  • Mobile First — підхід, за якого спочатку розробляють мобільну версію, а потім розширюють її для більших екранів (min-width).
  • Desktop First — підхід, за якого спочатку розробляють десктопну версію, а потім спрощують її для менших екранів (max-width).

🔭 Метатег viewport

<meta name="viewport"
  content="width=device-width,
  initial-scale=1">

width=device-width — ширина в’юпорту дорівнює ширині екрана пристрою. initial-scale=1 — початковий масштаб 100%.

Без цього метатега мобільні браузери використовують умовну ширину близько 980px і зменшують сторінку. Значення user-scalable=no не рекомендується: воно обмежує доступність сайту.

🧩 Синтаксис медіа-запиту

@media only|not тип and (умова) {
  /* CSS-правила */
}

Якщо медіа-тип не вказано, використовується значення за замовчуванням — all.

min-width: 600px — умова виконується, коли ширина в’юпорту 600px і більше.
max-width: 600px — умова виконується, коли ширина в’юпорту 600px і менше.

🖨️ Медіа-типи

  • all — усі пристрої (значення за замовчуванням);
  • screen — екран пристрою;
  • print — друкувальні пристрої, наприклад принтер;
  • speech — мовні синтезатори та програми для відтворення тексту вголос.

🔗 Логічні оператори

  • and — усі умови мають виконуватися одночасно: (min-width: 600px) and (max-width: 900px);
  • кома , — достатньо виконання хоча б однієї умови («або»);
  • not — інвертує результат усього запиту;
  • only — приховує запит від застарілих браузерів; у сучасних браузерах результат не змінює.

📱 Шаблон Mobile First

/* базові стилі: мобільна версія,
   медіа-запит не потрібен */
.menu { display: flex;
  flex-direction: column; }

/* від 768px: планшет і більші */
@media (min-width: 768px) {
  .menu { flex-direction: row; }
}

📐 Орієнтири для брейкпойнтів

  • ~600px — великий телефон;
  • ~768px — планшет;
  • ~1024px — ноутбук;
  • ~1440px — великий монітор.

Це орієнтири, а не стандарт. Брейкпойнт ставлять там, де макет втрачає зручність читання, а не під конкретну модель пристрою.

🧱 Flexbox: основні властивості

  • display: flex — робить елемент flex-контейнером;
  • flex-direction: column | row — напрямок осі: стовпчик або рядок;
  • flex-wrap: wrap — дозволяє переносити елементи на новий рядок;
  • flex: 1 1 200px — елемент може збільшуватися та стискатися, бажана ширина — 200px.

✅ Контрольний список

  • Додано метатег viewport.
  • Відсутнє горизонтальне прокручування.
  • Базові стилі підходять для мобільного екрана.
  • Немає фіксованої ширини блоків у px, більшої за екран телефона.
  • Не використано width: 100vw.
  • Сторінку перевірено в DevTools (F12) за різної ширини.
